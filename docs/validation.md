Vitest 8개: 로컬 시간 변환·검증 4개, 예약 생성·수정 폼·실행 이력·목록 취소 4개. Tauri IPC와 파일 선택은 UI 단위 테스트에서 모킹합니다. 실제 Tauri 이벤트, OS 트레이 및 권한 동작은 모킹한 UI 테스트로 검증하지 않습니다.

최초 네트워크 허용 환경에서 yarn.lock과 Cargo.lock을 생성·고정해야 합니다. 현재 yarn.lock은 경고 주석이 있는 미해석 부트스트랩 파일입니다. 의존성 버전이나 체크섬을 임의로 만들어 넣지 않았습니다. CI는 설치 시 실제 잠금 파일을 생성하도록 구성했으며 정식 릴리스 전에 --frozen-lockfile/--locked로 고정해야 합니다.

## OS 수동 검증 체크리스트

아래 항목은 모두 미검증입니다. Windows와 macOS의 별도 사용자 계정/테스트 PC에서 각각 수행하고 OS·CLI·터미널 버전, 날짜, 결과를 기록해야 합니다.

- [ ] Windows cmd: 30초 뒤 예약, 한글·공백 프로젝트 폴더, 여러 줄 특수문자 프롬프트, 실제 콘솔 출력과 정상 종료 이력.
- [ ] Windows PowerShell / PowerShell 7: 별도 창, 래퍼가 종료할 때까지 셸이 대기, 종료 후 창 유지/해제.
- [ ] Windows Terminal + cmd: 새 창/탭, Unicode 경로와 인자, 프로필과 무관한 명시적 cmd 실행, 결과 추적.
- [ ] Git Bash: git-bash 런처 -c 인자 처리, mintty에서 Windows GUI 래퍼의 stdin/stdout/stderr 연결, 한글 출력과 결과 추적. 이 조합은 특히 실기 확인이 필요함.
- [ ] macOS Terminal.app / iTerm2: 실제 새 세션, 최초 Automation 허용/거부, CLI 출력과 종료 코드, 시스템 설정에서 권한 재설정.
- [ ] macOS 터미널 유지 해제: 래퍼 종료 후 셸은 exit하지만 창 닫힘은 터미널 프로필의 종료 정책을 따를 수 있음. 실제 창 닫힘 요구와 차이가 있는지 확인해야 함.
- [ ] Codex / Claude / Gemini 실제 버전별 stdin 비대화형 실행. 인증 만료·사용량 제한·네트워크 오류·승인 거부를 기본 CLI 정책 그대로 확인.
- [ ] 메인 창 닫기 → 트레이 유지 → 예약 실행 → 트레이 클릭/메뉴로 복원. macOS 메뉴 막대와 Cmd+Q 처리도 확인.
- [ ] 트레이 완전 종료 → 예약 미실행 → 재시작 시 missed. 실행 중인 CLI가 앱 종료 후에도 계속 진행하고 결과가 복구되는지 확인.
- [ ] 같은 초에 여러 작업, 수동 실행 연타, 단일 인스턴스, 앱 강제 종료 직전/직후 상태 저장과 복구.
- [ ] 절전 복귀, 시각 앞/뒤 변경, DST 중복·존재하지 않는 시각, OS 시간대 변경.
- [ ] 터미널/CLI/폴더 삭제, 파일 접근 거부, 디스크 부족, JSON 손상·백업 복구, 결과 파일 손상.
- [ ] 작업 삭제 후 이력 보존 및 보존 기간 정리. 프롬프트가 이력에 포함되지 않는지 실제 JSON 점검.
- [ ] Windows 깨끗한 PC에서 EXE만 이동 실행, WebView2 설치/미설치, 정적 CRT 의존성 확인.
- [ ] 서명/공증 ZIP의 체크섬 및 보안 검사. 미서명 산출물 표시와 실제 경고 확인.

## 명시적인 제한과 미완료

- Warp는 설치 감지와 비지원 안내만 구현했습니다. 실행 선택은 비활성화합니다.
- 네이티브 컴파일, 정식 프론트엔드 빌드, Vitest 및 Rust 테스트는 미검증입니다. 컴파일/API 호환성 문제가 남아 있을 수 있습니다.
- OS Automation 권한의 현재 상태를 선제적으로 판정하지 않고 실제 실행 실패 및 권한 안내를 제공합니다. 알림 플러그인의 Granted 응답은 실제 OS 알림 설정을 보장하지 않습니다.
- GUI 앱 PATH 차이를 줄이기 위해 PATH와 일반적인 사용자·Homebrew 설치 위치를 탐색합니다. nvm/asdf 등 모든 셸 초기화 구성을 자동으로 재현하지 않으며 수동 경로를 지정할 수 있습니다.
- 결과를 남기지 않은 래퍼 종료는 unknown으로 기록하고 수동 재실행 전 외부 CLI 상태 확인을 안내합니다. PID 재사용/프로세스 조회 거부에서는 중복 실행 방지를 위해 상태가 잠길 수 있습니다.
- JSON 세 파일 전체의 트랜잭션은 보장하지 않습니다. 실행 전 이력 저장과 재시작 대조로 중복 실행 가능성을 줄이며 정확히 한 번 실행을 주장하지 않습니다.
- 작업 스케줄러/launchd, 절전 해제, 앱 완전 종료 후 실행, 반복 예약, 자동 업데이트와 자동 시작은 구현 범위에서 제외했습니다.
